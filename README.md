# Hand in Hand

A static sign-language learning project centered on Zimbabwean Sign Language (ZSL), with supplementary sign photos and a British Sign Language (BSL) fingerspelling tool. It uses HTML, CSS, browser JavaScript, and JSON sign indexes; no PHP or build step is required.

## Run locally or deploy

Serve the project folder from any static web server or hosting service, then open `index.html`. A local deployment uses the HTML, CSS, JavaScript, images, and dictionary files, preserving their relative paths.

### Publish with GitHub Pages

The repository includes a GitHub Actions workflow for publishing the static site. Push this project to a GitHub repository on the `main` branch, then select **Settings → Pages → Build and deployment → GitHub Actions**. The workflow publishes the site on each push to `main`; the public URL will be `https://<username>.github.io/<repository>/`. Camera and microphone features require HTTPS, which GitHub Pages provides. The workflow publishes the indexed sign photos and ZSL alphabet images, but excludes source PDFs and unrelated local documents. It verifies that every indexed image is present and no PDF is included in the Pages artifact. Source PDFs remain in the repository.

Search shows ZSL sign photos first. Supplementary sign photos are used only when no ZSL photo matches; the interface does not link to or publish the source PDFs. If neither photo index has a match, the word is shown using the ZSL fingerspelling images in `images/ZSL_signs/`.

## What is included

- The home page links to the ZSL translator, supplementary sign-photo lookup, and BSL fingerspelling tool.
- The home page also links to `voice-to-sign.html`, where typed or browser-recognized English is presented as sign photos or ZSL fingerspelling. Playback supports pause, stepping, and speed control. It is not continuous signing footage or a fluent sign-language translation.
- The home page also links to `videototext.html` (“Video to Text”). It requests camera permission and supports manual transcript editing and automatic sign-photo lookup. Genuine camera transcription requires a ZSL-specific model: define `window.HAND_IN_HAND_VIDEO_TO_TEXT_PROVIDER` before `js/video-to-text.js` loads, with `language: "zsl"` (or `languages` containing `"zsl"`) and an async `recognizeFrame({ video, language })` method returning `{ text, isFinal, confidence }`. The method is called about every 300 ms; interim results should set `isFinal: false`, and only new finalized text should set `isFinal: true`. Confidence, when supplied, must be between 0 and 1. Without a compatible provider, the page shows camera preview but deliberately does not guess signs. Transcript words search the sign-photo indexes first, then use ZSL fingerspelling when neither has an entry. Camera access requires HTTPS or localhost. A provider may transmit camera frames outside the browser; review its privacy terms and disclose that processing before enabling it. No sign-recognition model or dataset is bundled.
- `videototext.html` includes an optional local ZSL sample-collection workflow for academic research. After camera permission, a ZSL gloss, English meaning, pseudonymous signer code, and an informed-consent confirmation are required. Each recorded WebM clip and its annotations CSV are downloaded to the user's device; this static page does not upload or retain the recordings. Obtain institutional ethics approval and signer consent, secure collected clips, and follow approved retention/deletion rules. Use the collected and reviewed corpus to train and evaluate a ZSL-specific temporal model; split evaluation by signer to reduce identity leakage. ASL corpora such as [WLASL](https://github.com/dxli94/WLASL) are not ZSL and have their own computational-use terms; they can inform methods, but do not substitute for labeled ZSL data or authorize training on ZSL.
- The downloaded [Sign Language Digits Dataset](https://github.com/ardamavi/Sign-Language-Digits-Dataset) can be used for a separate, local ASL digit-image classification experiment. With Python, NumPy, and OpenCV installed, run `python scripts/asl_digits_demo.py train "C:\path\to\Sign-Language-Digits-Dataset-master.zip"` and then `python scripts/asl_digits_demo.py camera`. Training writes a nearest-neighbor model, a copy of the dataset license, and a random-image-split evaluation report under `models/asl-digits/` (ignored by Git). The optional webcam tool explicitly identifies predictions as ASL digits, not ZSL; it does not connect to or change the ZSL camera/transcription flow. This still-image dataset cannot train a video recognizer or ZSL translator. Its random-image test split is not signer-independent; use consented, signer-labeled ZSL video and signer-separated evaluation for ZSL research.
- The voice-to-sign player has an optional provider hook for genuine ZSL video. To enable it, a trusted same-origin integration script must define `window.HAND_IN_HAND_SIGN_VIDEO_PROVIDER` before `js/voice-to-sign.js` runs. The provider declares `language: "zsl"` (or `languages: ["zsl"]`) and implements `generateVideo({ text, language })`, returning a promise for `{ language: "zsl", videoUrl: "https://.../sign-video.mp4" }`. The page only accepts HTTP(S) or blob video URLs, and uses the existing dictionary-photo/fingerspelling sequence if no provider is configured or generation fails. Do not put private API keys in browser code. If the provider sends transcript text to another service, disclose that and obtain appropriate user consent. No video-generation model or signing dataset is bundled with this static project.
- Search for a word or phrase on the home page to display its matching sign photo. ZSL photos take precedence, supplementary photos fill gaps, and words absent from both indexes use ZSL fingerspelling.
- The Zimbabwean translator can show a live English transcript and sign photos; unmatched words use the ZSL alphabet handshapes. Voice input requires a supported browser, microphone permission, and a secure HTTPS connection (localhost is also supported); speech recognition may use the browser's online speech service.
- Voice input on the voice-to-sign page requires a supported browser, microphone permission, and a secure HTTPS connection (localhost is also supported); speech recognition may use the browser's online speech service.
- The ordered lookup checks exact phrases, word entries, alternate English labels, and words inside multiword entries before using a fallback. Common grammatical variants and equivalents (such as "was" → "be", "not" → "no", and "I" → "me") use matching ZSL sign photos while keeping the typed word as the result-card heading. An exact supplementary photo is used only when no exact ZSL photo is available.
- ZSL fingerspelling images are stored in `images/ZSL_signs/` and appear only when neither sign-photo index has a match.
- `js/dictionary-index.js`, `js/pdf-sign-index.js`, and `js/joy-sign-index.js` index the PNG and JPEG sign photos. The GitHub Pages workflow copies only those indexed images and does not publish source PDFs.
- The home page uses a hosted Unsplash photograph as a decorative background; provide internet access to load that image. Its solid-color fallback remains in place if the photo service is unavailable.

The visual palette combines deep blue, violet, and warm amber to suggest trust, inclusion, and rehabilitation. It is an independent interpretation—not an official set of brand colors or a claim of endorsement by St Daniels Rehabilitation and Vocational Training Centre or Zimbabwe Epilepsy Survivors Trust. These tools are learning aids, not substitutes for fluent signers or qualified interpreters; sign languages are distinct languages, not word-for-word versions of spoken languages.
